# RSS 阅读器 v0.1 开发验证

日期：2026-09-15。设备：本地 Android 16 ARM64 模拟器（API 36）。构建：JDK 17、Gradle 9.6.0、Android Gradle Plugin 9.4.0、编译 API 37。本次验证的 APK SHA-256：`735821753e0d8e4b2f364d9e99e0a04288910650ad1942524cd684c05d7a53ea`。

## 已通过

`gradle :app:testDebugUnitTest :app:assembleDebug` 成功，项目自带的 `./gradlew --version` 也独立下载并启动 Gradle 9.6.0。7 个单元测试全部通过，覆盖 RSS/Atom 与 XHTML 解析、普通网页拒绝、GB2312/GBK 解码、首次最新 20 篇以及快速滑动中间条目的范围计算。

| 模拟器用例 | 实际结果 |
|---|---|
| 本地固定 RSS 25 篇首次导入 | 25 篇入库，最新 20 篇未读；默认未读列表从第 06 篇开始，最旧优先。 |
| [IT之家 RSS](https://www.ithome.com/rss/) | 首次获取 60 篇，20 篇未读；标题、摘要、缩略图和正文正常呈现。随后冷启动刷新新增文章保持未读，已有已读状态不变。 |
| Atom 固定源 | 预览显示 1 篇，确认后 1 篇未读。 |
| 重复地址与普通网页 | 重复 IT之家地址提示“该订阅源已添加”；普通 HTML 提示“内容不是 RSS 或 Atom 订阅源”；两者都保留输入。 |
| 列表普通、快速和反向滑动 | 完全跨过顶部的第 06–11 篇均已读，未跨过的第 12 篇仍未读；反向滑动未增加已读。 |
| 进入文章并返回 | 入页未读数减少 1；当前列表保留文章原位并灰显；重新进入源后已读文章从未读过滤消失。 |
| 手动刷新与靠前新文章 | 重复文章不再导入；长列表新增发布日期更早的文章时，原顶部文章保持同一屏幕坐标，插入不误标已读。短列表所有行都能容纳时，自然显示新行。 |
| 批量已读 | 确认框显示当前来源名称和 14 篇快照；确认后该来源未读归零，重新进入显示读完状态；“全部”只显示该来源 25 篇，从第 01 篇开始。 |
| 已读 30 天清理 | 在测试数据库设一篇过期已读、一篇很旧的未读；冷启动后过期已读删除、未读保留、去重记录增加 1。再次刷新同源，已清理文章没有被重新导入。 |
| 刷新失败及重试 | 固定源临时返回普通网页时显示错误，29 篇缓存文章和未读状态仍在；恢复 RSS 后错误清除，文章数不变。 |
| 订阅源管理 | 长按菜单有重命名和删除；重命名后文章与未读数不变；删除确认后仅该源及其文章被清除。 |
| 阅读字号、位置、图片和原文 | 字号从 18 调到 22 后冷启动仍为 22；正文保存位置 1175，重开显示中段；再次打开未延长首次已读时间；图片点击出现大图层，原文交给系统浏览器。 |
| 浅色主题 | 系统切到夜间模式时，应用仍显示浅色。 |

## 尚未完成的验收

这是可试用的 debug 版本，还没有按 [完整验收清单](RSS阅读器验收用例.md) 完成发布门槛。真实手机适配尚未测试；后台返回的 15 分钟自动刷新边界、无网络时的实际设备表现、刚满 30 天的精确时钟边界、100 篇不同高度行的快速滑动、批量已读同时到达新文章、无日期及同日期排序、系统大字体和图片加载失败，仍需专项验收。当前没有已确认的功能失败；这些未测项不能视为通过。

调试版由 Android 默认 debug 密钥签名，正式发布或长期更新前应使用固定签名密钥重新构建并完成上述验收。
