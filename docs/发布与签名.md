# 发布与签名

Android 使用应用 ID 和签名证书共同确认应用身份。正式版本必须一直使用同一把 release 私钥，才能覆盖安装并保留现有本地数据。

## 当前正式签名身份

以下信息来自已发布的 `v0.1.1` APK，属于可公开校验的信息：

| 项目 | 当前值 |
|---|---|
| Application ID | `com.codex.rssreader` |
| Key alias | `rss-reader` |
| Keystore 容器格式 | `PKCS12` |
| 密钥算法 | RSA 4096 bit |
| 签名者数量 | 1 |
| APK 签名方案 | v2 |
| 签名证书 SHA-256 | `1d5719d4426f0b1d1faedb5fb5aef75884024a2d379caee9edfd950c401aaf87` |
| 公钥 SHA-256 | `276d60bb72d6cf7a4549f2239ed2a003d56cf40065ef407e8ba02ec5e111f6ee` |

签名证书 SHA-256 是判断正式包是否由当前密钥签发的主要基准。后续每个 Release 的该值都必须完全一致；不一致时应停止安装和发布，先排查密钥来源。

证书指纹、公钥、alias、算法和容器格式可以公开。JKS/PKCS12 文件包含私钥，即使文件本身有密码也不能公开。

## 验证下载的 APK

把 APK、`SHA256SUMS.txt` 和 `SIGNING_CERT.txt` 下载到同一目录。在 macOS 中先验证文件摘要：

```sh
shasum -a 256 rss-reader-0.1.1-release.apk
cat SHA256SUMS.txt
```

两处 APK SHA-256 应一致。再使用 Android Build Tools 验证签名：

```sh
"$ANDROID_HOME/build-tools/36.0.0/apksigner" verify \
  --verbose \
  --print-certs \
  rss-reader-0.1.1-release.apk
```

检查结果应满足：

- `Verifies` 成功。
- `Verified using v2 scheme` 为 `true`。
- 签名者数量为 1。
- 证书 SHA-256 与本文记录的值一致。

APK 文件摘要会随版本变化，证书 SHA-256 应在继续使用当前正式密钥期间保持不变。

## GitHub Actions 正式发布

仓库需要配置四个 Actions Secrets：

- `ANDROID_KEYSTORE_BASE64`
- `ANDROID_KEYSTORE_PASSWORD`
- `ANDROID_KEY_ALIAS`
- `ANDROID_KEY_PASSWORD`

Secret 只保存值，名称可以公开。推送 `v*` 标签会运行 `.github/workflows/android-release.yml`，执行测试、固定密钥签名、`apksigner` 验证、SHA-256 计算，并创建 GitHub Release。例如发布 `v0.1.2`：

```sh
git tag -a v0.1.2 -m "Release v0.1.2"
git push origin v0.1.2
```

标签名会成为 `versionName`；GitHub Actions 的递增运行编号会成为 `versionCode`。仅从 Actions 页面手动运行会生成保留 30 天的 Artifact，不会创建长期 Release。

## 本地构建正式包

将 keystore 放在仓库外，使用绝对路径。下面的密码由终端静默读取，不会写入 shell 历史：

```sh
export ANDROID_KEYSTORE_PATH="/绝对路径/rss-reader-release.jks"
export ANDROID_KEY_ALIAS="rss-reader"
export VERSION_NAME="0.1.2"
export VERSION_CODE="3"

read -s "ANDROID_KEYSTORE_PASSWORD?Keystore password: "
export ANDROID_KEYSTORE_PASSWORD
echo
read -s "ANDROID_KEY_PASSWORD?Key password: "
export ANDROID_KEY_PASSWORD
echo

./gradlew :app:testDebugUnitTest :app:assembleRelease
"$ANDROID_HOME/build-tools/36.0.0/apksigner" verify \
  --verbose \
  --print-certs \
  app/build/outputs/apk/release/app-release.apk

unset ANDROID_KEYSTORE_PASSWORD ANDROID_KEY_PASSWORD
```

发布前还需确认 `VERSION_CODE` 大于已经安装或发布的版本。不要用本地随意填写的版本号覆盖正式发布流程中的版本管理。

## 私钥与密码保存边界

以下内容不能提交到 Git、写进文档、Issue、Release 或聊天记录：

- release keystore 原文件。
- keystore 的 Base64 文本；Base64 只是编码，不是加密。
- keystore password 和 key password。
- 包含上述值的 `.env`、`key.properties`、终端日志或截图。

建议至少保留两份加密备份，放在不同位置；密码单独保存在密码管理器中。每次更换电脑或备份介质后，应实际恢复一次，并通过本文的证书 SHA-256 验证恢复出的密钥身份。仓库的 `.gitignore` 已排除常见 keystore、Base64 和本地签名配置文件，但仍应在提交前检查 `git status`。

如果正式密钥丢失或改用另一把密钥，Android 不允许新包直接覆盖现有安装。当前应用没有数据导出/导入功能，因此卸载旧包会同时删除本地订阅和阅读状态。

安装冲突、Actions 签名失败和 Release 未生成的处理步骤见[故障排查](故障排查.md)。
