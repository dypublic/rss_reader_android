# RSS 阅读器首版验收用例

日期：2026-09-15

这是完整执行清单，不是测试报告。已执行的用例和未完成的验收分别记录在《RSS阅读器开发验证.md》；模拟器环境说明另见《Android模拟器使用说明.md》。

标记：P0 为核心逻辑，必须通过；P1 为首版体验，同样需验收。开发边界处理见需求文档第 8 节。

## 1. 固定测试数据

- 来源 A：25 篇，唯一 ID，发布时间依次递增；刷新版本新增 2 篇，并重复返回已有文章。
- 来源 B：5 篇，用于不足 20 篇的首次导入。
- 来源 C：缺日期、同日期、无图、无摘要、长标题、全文和仅摘要的混合内容。
- 来源 D：超时、HTTP 错误、非订阅 XML、畸形内容和空订阅。
- 滚动数据：100 篇未读，包含不同高度条目，可复现快速跨越。
- 时间数据：通过可控时钟构造已读 29 天 23 小时、刚满 30 天、未读超过 30 天的文章，不依赖实际等待。

## 2. 订阅与导入

| ID | 优先级 | 操作 | 预期 |
|---|---|---|---|
| S01 | P0 | 添加来源 A | 展示来源名；确认后 25 篇入库，最新 20 篇未读，最旧 5 篇已读 |
| S02 | P0 | 添加来源 B | 5 篇全部未读 |
| S03 | P0 | 再次添加同一地址 | 不重复创建来源及文章 |
| S04 | P1 | 输入无效地址或非 RSS 内容 | 显示可理解错误并保留输入 |
| S05 | P1 | 重命名后重启 | 新名称保留，文章和未读数不变 |
| S06 | P0 | 删除来源，分别取消和确认 | 取消无变化；确认后来源及文章移除，该来源未读数消失，其他来源不变 |
| S07 | P0 | 加载 Atom 测试源 | 正常导入，与 RSS 阅读行为一致 |
| S08 | P0 | 添加多个来源，再将其中一个全部读完并刷新 | 来源顺序保持添加顺序；零未读来源仍显示，数量为 0 |
| S09 | P1 | 长按订阅源，分别重命名、取消删除和确认删除 | 菜单提供对应操作；重命名后文章状态不变；取消删除无变化，确认后来源和本地文章移除 |

## 3. 列表与已读

| ID | 优先级 | 操作 | 预期 |
|---|---|---|---|
| L01 | P0 | 进入来源 A 的列表 | 默认未读，20 篇按最旧优先，起点为这 20 篇中最旧的一篇 |
| L02 | P0 | 切换当前来源的“全部” | A 的 25 篇按最旧优先，不混入其他来源；切换本身不新增已读 |
| L03 | P0 | 点击未读文章并返回 | 文章已读、未读数减 1；原列表位置保留，文章原位变灰 |
| L04 | P0 | 让条目部分越过顶部 | 该条目仍未读 |
| L05 | P0 | 继续让条目完整越过顶部 | 立即已读，该来源未读数减 1，其他来源不变 |
| L06 | P0 | 快速滑过多个条目 | 所有跨过顶部的条目已读，无停留时间门槛，包括未完整渲染的中间条目；当前仍可见条目不误标 |
| L07 | P0 | 向回翻阅，使条目从底部离开 | 不触发新增已读 |
| L08 | P0 | 首次加载、筛选切换、刷新、位置恢复 | 系统引起的位移不触发滚动已读 |
| L09 | P0 | 滚动已读后继续浏览 | 已读条目保留位置并变灰，不即时消失造成跳动 |
| L10 | P0 | L09 后刷新或返回订阅页再进入 | 已读条目从未读列表移除，从最旧未读开始；总数正确 |
| L11 | P0 | 重复打开、重复跨过同一已读文章 | 不重复扣未读数，不延长已读时间 |
| L12 | P0 | 当前来源点击全部已读，分别取消和确认 | 确认框显示来源名称与篇数；取消不改变状态，确认只影响该来源，其他来源不变 |
| L13 | P0 | 查看订阅页 | 仅显示各订阅源，没有跨来源的全部文章入口 |
| L14 | P0 | 批量已读期间新增文章 | 新增文章保持未读，不扩大操作开始时的文章范围 |
| L15 | P1 | 所有未读清空 | 显示已读完及切换全部入口，无空白或错误提示 |
| L16 | P0 | 切到当前来源的“全部”，向下划过未读和已读条目 | 未读条目越过顶部后标为已读；已读条目状态和计时不变，其他来源不变 |
| L17 | P0 | 来源含无效或缺失发布时间及相同时间文章 | 无日期文章按首次获取时间排序；相同时间次序稳定，刷新后不随机重排 |

滚动自动化应根据条目的布局边界计算实际越过集合，核对文章 ID 和数据库状态，不能仅断言未读数减少或复制实现算法。

## 4. 刷新与持久化

| ID | 优先级 | 操作 | 预期 |
|---|---|---|---|
| R01 | P0 | A 刷新新增 2 篇并返回旧文章 | 只增加 2 篇未读，原文章状态保留，无重复 |
| R02 | P0 | 多来源刷新，其中一个失败 | 成功来源正常更新，失败来源保留数据并能重试 |
| R03 | P0 | 断网打开已缓存文章 | 文字可读；刷新失败有反馈，数据不丢失 |
| R04 | P0 | 强制停止 App 后重新打开 | 订阅、阅读状态、字号和正文阅读位置保留 |
| R05 | P1 | 连续点击刷新 | 不产生重复任务、文章或错误计数 |
| R06 | P0 | 刷新带来排序靠前的新文章 | 现有阅读位置稳定，新增或位移条目不会自动已读 |
| R07 | P0 | 重新启动 App | 自动刷新订阅源 |
| R08 | P0 | 从后台返回，距上次刷新不足 15 分钟 | 不自动刷新；手动下拉仍能刷新 |
| R09 | P0 | 从后台返回，距上次刷新超过 15 分钟 | 自动刷新 |

## 5. 30 天清理

| ID | 优先级 | 操作 | 预期 |
|---|---|---|---|
| D01 | P0 | 启动并清理时间未满 30 天的已读文章 | 保留 |
| D02 | P0 | 启动并清理刚满 30 天的已读文章 | 删除本地文章内容，保留去重标识 |
| D03 | P0 | 对很旧的未读文章执行清理 | 始终保留 |
| D04 | P0 | 第 29 天再次打开已读文章，再推进到第 30 天 | 仍按首次标为已读的时间清理 |
| D05 | P0 | 清理后 RSS 再次返回同一文章 | 不重新导入成未读 |
| D06 | P0 | 首次导入的旧文章经过 30 天 | 从导入标为已读时间计算，满足条件后清理 |

## 7. 执行方式与发布门槛

- 自动化：订阅解析、首次 20 篇、排序、去重、状态转换、清理边界和批量范围。
- Android 界面自动化：滚动边界、快速跨越、返回位置、筛选与刷新不误标。
- 模拟器人工验收：对照 UI、正文排版、字号、图片和系统返回行为。
- 真实来源联调：至少覆盖全文、摘要和带图来源，记录来源地址、执行时间和结果；实时内容不能替代固定用例。
- 发布要求：P0 全部通过；P1 完成检查，偏差必须明确记录并取得接受，不能默认为通过。
- 报告区分自动化、模拟器人工和真实手机结果；未测试项标为未测试。
