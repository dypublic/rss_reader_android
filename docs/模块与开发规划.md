# Android RSS 阅读器：模块与开发规划

日期：2026-09-15 · 依据《RSS阅读器产品需求.md》v1.0

## 总体做法

首版采用**一个 Android `app` 构建模块，按职责分包**。个人使用的应用只有订阅页、单来源文章列表、阅读页和设置页；现在拆成多个 Gradle 子模块会增加构建与依赖管理成本。把页面、数据来源和复杂阅读规则保持清晰边界，后续确有复用或构建瓶颈时再拆子模块。Android 官方也建议小型应用可以通过 `ui`、`data` 包组织层次，并让页面经由仓库访问数据。[官方架构建议](https://developer.android.com/topic/architecture/recommendations)

应用采用单 Activity：Compose 页面负责展示和接收操作；ViewModel 组织各屏幕状态；仓库统一读写本地数据。文章和订阅以本地数据库为唯一显示来源，网络刷新只负责更新数据库，因此离线时仍能读已下载文字。[Android 架构指南](https://developer.android.com/topic/architecture)，[离线优先指南](https://developer.android.com/topic/architecture/data-layer/offline-first)

## 功能模块

| 模块 | 主要职责 | 不承担的职责 |
|---|---|---|
| 应用外壳 `app` | 启动、页面导航、前后台事件、启动清理和刷新协调 | 不直接解析 RSS 或计算已读 |
| 订阅管理 `subscriptions` | 添加地址、验证、显示名称、长按重命名／删除、订阅源及未读数展示 | 不保存文章正文 |
| RSS 获取与解析 `feed` | HTTP 请求、RSS 2.0／Atom 解析、提取文章字段、处理网络或格式错误 | 不操作页面和已读状态 |
| 更新协调 `sync` | 逐来源刷新、去重与入库、首次最新 20 篇规则、失败隔离、合并重复刷新请求 | 不直接修改滚动位置 |
| 本地数据 `local` | 保存来源、文章、已读时间、阅读位置、去重记录；提供查询和事务 | 不决定页面外观 |
| 文章列表 `articles` | 未读／全部筛选、最旧优先排序、列表位置、下拉刷新与状态呈现 | 不直接请求 RSS 网络 |
| 已读规则 `readingstate` | 打开即已读、用户向下划出即已读、快速滑过范围处理、批量已读、30 天清理 | 不决定图标或颜色 |
| 正文阅读 `reader` | RSS 正文排版、字号、图片放大、阅读位置、打开原文 | 不抓取网页全文 |
| 偏好设置 `settings` | 全局字号等少量设置的持久化 | 不管理文章数据库 |

`readingstate` 与 `sync` 是首版最容易出错的部分，独立为可测试的规则类；它们仍在同一个 `app` 构建模块中。

## 建议的代码目录

```text
app/src/main/java/.../
  AppActivity.kt
  navigation/                 页面导航、启动与前后台协调
  ui/
    subscriptions/            订阅页、添加弹窗、长按菜单、ViewModel
    articles/                 列表、筛选、滚动事件、ViewModel
    reader/                   阅读页、图片预览、ViewModel
    settings/                 设置页、ViewModel
    components/               通用顶栏、文章条目、空态、错误提示
    theme/                    浅色配色、字号和间距
  model/                      来源、文章、阅读状态等应用模型
  data/
    feed/                     HTTP 客户端、RSS/Atom 解析与规范化
    local/                    Room 数据库、Entity、DAO
    preferences/              字号等偏好持久化
    repository/               SubscriptionRepository、ArticleRepository
  rules/
    sync/                     首次导入、去重、刷新合并
    readingstate/             划出判定、批量已读、30 天清理
```

页面 ViewModel 只依赖仓库和规则类，不直接调用 HTTP 客户端或 DAO。Room 负责结构化的本地数据；轻量偏好可用 DataStore。具体依赖版本在实现时按当时的官方兼容说明选取。[Room 官方文档](https://developer.android.com/training/data-storage/room)，[Android 架构建议](https://developer.android.com/topic/architecture/recommendations)

## 核心数据与流转

| 数据 | 最少需要保存的内容 | 用途 |
|---|---|---|
| `Subscription` | 本地 ID、订阅地址、显示名称、图标地址、添加顺序、上次刷新与错误 | 订阅页和来源管理 |
| `Article` | 本地 ID、来源 ID、源内标识、链接、标题、摘要、正文、图片、发布时间、首次获取时间、已读时间、阅读位置 | 列表、阅读、排序和清理 |
| `SeenArticle` | 来源 ID、源内稳定标识 | 文章内容清理后继续去重 |
| `ReaderPreferences` | 字号 | 全局阅读偏好 |

数据流：

```text
RSS/Atom 地址
  → 下载和解析
  → 规范化、识别来源内文章
  → 本地数据库事务：新增/更新、保留已读状态
  → 仓库查询流
  → 订阅页 / 单来源文章列表 / 阅读页

用户点击、向下划过、批量已读
  → 已读规则
  → 本地数据库事务
  → 未读数与页面状态同步更新
```

当 RSS 返回无效或缺失发布时间时，以首次获取时间排序；时间相同再用稳定键固定次序。首次添加选最新 20 篇未读，必须在**按时间确定最新篇目后**再写入已读状态。后续更新按文章稳定标识去重，不能重置已有的已读时间。详见[产品需求](产品需求.md)。

## 两处关键实现边界

**快速划过即已读。** 列表模块维护当前排序结果的文章 ID 快照，以及上一次与本次位于屏幕顶部的条目位置。只有用户真实向下滚动时，才把完整越过顶部的 ID 范围交给已读规则；快速滑动跨越的中间条目即使没被 Compose 完整渲染，也要包含。点击进入、返回、刷新插入、筛选切换、首次布局和自动恢复位置均不能作为用户划过事件。数据库批量更新后，当前未读列表保留已读条目原位变灰，重新进入或手动刷新再按真实状态过滤。

**30 天清理与去重。** App 启动时清理满 30 天的已读文章正文与本地记录，未读文章保持。清理前保留来源内稳定标识到轻量去重表；随后刷新即使 RSS 再返回这篇旧文章，也不能把它导入为新未读。删除订阅源则连其文章和去重记录一同删除。

## 开发顺序与每步验证

| 阶段 | 交付 | 验证重点 |
|---|---|---|
| 1. 项目和页面骨架 | 可在已配置模拟器启动；三页导航与浅色 UI；固定示例数据 | 参考图布局、系统返回、长标题和无图条目 |
| 2. 本地存储 | 来源、文章、字号、阅读位置持久化 | 强制停止并重开后数据与位置不丢失 |
| 3. 订阅与解析 | RSS 2.0／Atom 添加、错误提示、长按管理 | 有效、重复、无效及不足 20 篇来源 |
| 4. 更新与去重 | 启动、后台 15 分钟、手动刷新；首次 20 篇和新增规则 | 多来源部分失败、重复文章、滚动位置稳定 |
| 5. 已读与清理 | 打开、普通／快速划过、批量已读、30 天清理 | 划过边界、跳跃中间条目、刷新不误标、可控时间边界 |
| 6. 阅读体验 | 正文、字号、图片、外部原文和位置恢复 | 全文／仅摘要、离线文字、图片失败、返回列表位置 |
| 7. 联调交付 | APK、测试结果、已知问题 | P0 用例全部通过；模拟器人工 UI 对照和真实来源联调 |

每阶段先保证可运行，再加入下一层；最终验收以[验收用例](验收用例.md)为准。当前已实现 v0.1 调试版；实际源码分包和验证结果分别见项目根目录的 `README.md` 与[开发验证](开发验证.md)。
