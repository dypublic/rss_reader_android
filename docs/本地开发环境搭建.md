# 本地开发环境搭建

本文以 macOS 为例，从空白环境搭建到在 Android 模拟器中运行 RSS 阅读器。项目的 CI 使用 JDK 17；本地建议保持同一版本。源码自带 Gradle Wrapper，不需要另装 Gradle。

## 1. 环境要求

| 组件 | 项目要求 |
|---|---|
| JDK | 17 |
| Gradle | 9.6.0，由 `./gradlew` 自动管理 |
| Android SDK Platform | API 37.0，编译使用 |
| Android SDK Build Tools | 36.0.0 |
| Android Platform Tools | 当前 SDK 可用版本，提供 `adb` |
| Android Emulator | 当前 SDK 可用版本 |
| 模拟器系统 | Android 16 / API 36；Apple Silicon 用 `arm64-v8a`，Intel Mac 用 `x86_64` |
| 设备最低系统 | Android 8.0 / API 26 |

完整 SDK、系统镜像和一个虚拟设备通常需要约 4 GB，快照和构建缓存会继续占用空间。首次构建还需要访问 Google Maven、Maven Central 和 Gradle 官方下载站。

## 2. 安装 JDK 17

安装任一标准 JDK 17，例如 Eclipse Temurin 17 或 Amazon Corretto 17。安装后在终端执行：

```sh
/usr/libexec/java_home -V
export JAVA_HOME="$(/usr/libexec/java_home -v 17)"
export PATH="$JAVA_HOME/bin:$PATH"
java -version
```

`java -version` 应显示 17。如果看到 `Unable to locate a Java Runtime`，说明 JDK 尚未安装，或者 `JAVA_HOME` 没有指向已安装的 JDK。

建议将下面两行加入 `~/.zshrc`，新终端会自动使用 JDK 17：

```sh
export JAVA_HOME="$(/usr/libexec/java_home -v 17)"
export PATH="$JAVA_HOME/bin:$PATH"
```

Android Studio 自带的 JDK 也可以用于构建。在 Android Studio 的 Gradle 设置中选择 `Embedded JDK`；仅使用终端时，单独安装 JDK 17 更直观。

## 3. 安装 Android Studio 和 SDK

推荐安装 [Android Studio](https://developer.android.com/studio)，然后打开 **Settings → Languages & Frameworks → Android SDK**。安装这些组件：

- SDK Platforms：Android API 37.0。
- SDK Tools：Android SDK Build-Tools 36.0.0、Android SDK Platform-Tools、Android Emulator、Android SDK Command-line Tools（latest）。
- 用于模拟器的系统镜像：Android 16 / API 36，Default Android System Image；Apple Silicon 选择 ARM 64 v8a，Intel Mac 选择 x86_64。这个最简镜像不含 Google APIs 和 Play Store，本应用不需要它们。

macOS 默认 SDK 路径是 `$HOME/Library/Android/sdk`。在 `~/.zshrc` 中加入：

```sh
export ANDROID_HOME="$HOME/Library/Android/sdk"
export PATH="$ANDROID_HOME/platform-tools:$ANDROID_HOME/emulator:$ANDROID_HOME/cmdline-tools/latest/bin:$PATH"
```

重新打开终端，验证工具可用：

```sh
sdkmanager --version
adb version
emulator -version
```

### 只用命令行安装 SDK 组件

先从 Android Studio 官网下载 Command line tools，并将内容放到 `$ANDROID_HOME/cmdline-tools/latest/`，确保存在 `$ANDROID_HOME/cmdline-tools/latest/bin/sdkmanager`。然后执行：

```sh
sdkmanager --licenses
sdkmanager \
  "platform-tools" \
  "emulator" \
  "platforms;android-37.0" \
  "build-tools;36.0.0" \
  "system-images;android-36;default;arm64-v8a"
```

Intel Mac 将最后一项的 `arm64-v8a` 改为 `x86_64`。

## 4. 获取项目并配置 SDK 路径

```sh
git clone https://github.com/dypublic/rss_reader_android.git
cd rss_reader_android
```

环境变量 `ANDROID_HOME` 已正确设置时，Android Gradle Plugin 可以找到 SDK。也可以在项目根目录创建不提交 Git 的 `local.properties`：

```properties
sdk.dir=/Users/你的用户名/Library/Android/sdk
```

检查 Java、Gradle 和项目配置：

```sh
java -version
./gradlew --version
./gradlew :app:testDebugUnitTest :app:assembleDebug
```

首次执行时 Wrapper 会下载 Gradle 9.6.0，Gradle 还会下载项目依赖。测试与构建成功后，APK 位于：

```text
app/build/outputs/apk/debug/app-debug.apk
```

## 5. 创建并运行最简模拟器

用 Android Studio 的 **Device Manager** 创建 Pixel 6、Android 16 / API 36、Default Android System Image 虚拟设备，命名为 `RSS_Android_16`。不要选择带 Google APIs 或 Play Store 的镜像，本项目验证不依赖这些服务。

也可以用命令行创建。Apple Silicon 执行：

```sh
echo no | avdmanager create avd \
  --force \
  --name RSS_Android_16 \
  --package "system-images;android-36;default;arm64-v8a" \
  --device "pixel_6"

emulator -avd RSS_Android_16
```

Intel Mac 将包名中的 `arm64-v8a` 改为 `x86_64`。模拟器进入桌面后，在另一个终端执行：

```sh
adb devices
adb shell getprop sys.boot_completed
```

第二条命令返回 `1` 表示系统已启动完成。

## 6. 安装并启动应用

```sh
./gradlew :app:testDebugUnitTest :app:assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb shell am start -n com.codex.rssreader/.MainActivity
```

首次验证可添加 IT之家订阅地址：

```text
https://www.ithome.com/rss/
```

应能预览来源名称并添加；首次获取的最新 20 篇为未读，文章列表按最旧优先显示。完整操作检查见[验收用例](验收用例.md)。

## 7. 在 Android Studio 中开发

1. 选择 **Open**，打开仓库根目录。
2. 等待 Gradle Sync 完成。
3. 在 Gradle JDK 中选择已安装的 JDK 17。
4. 选择 `RSS_Android_16` 设备和 `app` 运行配置。
5. 点击 Run。单元测试可从 Gradle 面板执行 `app → Tasks → verification → testDebugUnitTest`。

## 8. 常见问题

### 找不到 Java Runtime

先确认 `/usr/libexec/java_home -V` 能列出 JDK 17，再设置 `JAVA_HOME`。安装 Android SDK 不会自动为普通终端配置 Java。

### SDK location not found

确认 `ANDROID_HOME` 指向真实 SDK 目录，或创建 `local.properties`。不要把 `local.properties` 提交到仓库，因为不同电脑的绝对路径不同。

### License 未接受

```sh
sdkmanager --licenses
```

逐项输入 `y`，然后重试构建。

### `adb` 或 `emulator` 找不到

确认 `~/.zshrc` 的 `PATH` 包含 `$ANDROID_HOME/platform-tools` 和 `$ANDROID_HOME/emulator`，然后打开新终端。

### 模拟器镜像架构不匹配

Apple Silicon 使用 `arm64-v8a`；Intel Mac 使用 `x86_64`。删除错误的虚拟设备后，用匹配的镜像重建。

### 依赖下载失败

确认当前网络能访问 Google Maven、Maven Central 和 `services.gradle.org`。缓存完整后，日常增量构建通常不需要重新下载。

## 9. 本地正式包

日常开发使用 debug 包。需要生成可升级的正式包时，必须使用项目固定的 release keystore；配置方法和验证基准见[发布与签名](发布与签名.md)。不要临时新建另一个签名密钥，否则生成的 APK 无法覆盖安装现有正式版本。
