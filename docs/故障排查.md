# 故障排查

本文按症状给出 RSS 阅读器的排查顺序。第一次搭建环境先看[完整本地开发环境搭建](本地开发环境搭建.md)，正式包相关问题同时参考[发布与签名](发布与签名.md)。

## 1. 先保留现场

出现问题后，先记录以下信息，再清缓存、卸载应用或重建模拟器：

- 使用的提交、版本名和 APK 来源。
- 设备或模拟器型号、Android 版本与 CPU 架构。
- 可复现的操作步骤、界面错误原文和发生时间。
- 出问题的订阅地址；如果地址含访问令牌，不要公开完整地址。
- 是 debug 包还是从 GitHub Releases 下载的正式包。
- 安装、构建或 GitHub Actions 的完整失败步骤和末尾错误日志。

不要为了排查直接清除应用数据或卸载正式包。当前应用没有数据导出功能，清除数据或卸载会删除本地订阅、文章和阅读状态。

## 2. 快速判断问题范围

| 症状 | 优先检查 |
|---|---|
| Gradle 无法启动 | JDK 17、`JAVA_HOME`、SDK 路径 |
| 编译时报缺少 Android 平台 | API 37.0、Build Tools 36.0.0、SDK license |
| 模拟器没有出现在 `adb devices` | 模拟器是否启动完成、Platform Tools、设备连接状态 |
| APK 无法覆盖安装 | debug/release 签名是否一致、`versionCode` 是否递增 |
| 无法添加订阅 | 地址是否直接返回 RSS 2.0 或 Atom、网络和 HTTP 状态码 |
| 已添加来源刷新失败 | 来源服务是否可用、TLS/网络、返回内容是否仍为订阅 XML |
| 文章数量或顺序看起来异常 | 最新 20 篇未读规则、未读/全部筛选、最旧优先排序 |
| 图片不显示但文字正常 | 图片仍需联网、图片地址或服务器防盗链 |
| GitHub 没有 Release | 是否推送了 `v*` 标签；手动 workflow 只生成 Artifact |

## 3. 收集 Android 日志

先确认设备连接：

```sh
adb devices
adb shell dumpsys package com.codex.rssreader | grep -E "versionName|versionCode"
```

清空旧日志，重现一次问题，再导出：

```sh
adb logcat -c
# 在设备上重现问题
adb logcat -d > rss-reader-logcat.txt
```

只观察当前应用进程可以使用：

```sh
adb logcat --pid="$(adb shell pidof com.codex.rssreader)"
```

应用崩溃时重点查找 `FATAL EXCEPTION`、`AndroidRuntime` 和紧随其后的 `Caused by`。日志可能包含订阅地址和文章内容，公开前先检查并删除个人信息或访问令牌。

## 4. 本地构建失败

### `Unable to locate a Java Runtime`

```sh
/usr/libexec/java_home -V
export JAVA_HOME="$(/usr/libexec/java_home -v 17)"
export PATH="$JAVA_HOME/bin:$PATH"
java -version
```

如果第一条命令没有列出 17，先安装 JDK 17。Android SDK 和 JDK 是两套独立组件。

### `SDK location not found`

```sh
export ANDROID_HOME="$HOME/Library/Android/sdk"
export PATH="$ANDROID_HOME/platform-tools:$ANDROID_HOME/emulator:$ANDROID_HOME/cmdline-tools/latest/bin:$PATH"
```

也可以在仓库根目录创建 `local.properties`：

```properties
sdk.dir=/Users/你的用户名/Library/Android/sdk
```

### 缺少 Platform 或 Build Tools

```sh
sdkmanager --licenses
sdkmanager "platforms;android-37.0" "build-tools;36.0.0" "platform-tools"
```

### Gradle 依赖下载失败

确认网络能访问 Google Maven、Maven Central 和 `services.gradle.org`。先重试同一命令；仍失败时获取详细日志：

```sh
./gradlew --no-daemon :app:testDebugUnitTest :app:assembleDebug --stacktrace --info
```

如果 Gradle 进程状态异常，可以执行：

```sh
./gradlew --stop
./gradlew clean
./gradlew --no-daemon :app:testDebugUnitTest :app:assembleDebug
```

`clean` 会删除构建产物，但不会删除源码、应用安装或设备数据。

## 5. 模拟器和 ADB

### `adb devices` 没有设备

等待模拟器进入桌面，再执行：

```sh
adb kill-server
adb start-server
adb devices
adb shell getprop sys.boot_completed
```

最后一条返回 `1` 才表示 Android 启动完成。真实手机显示 `unauthorized` 时，需要解锁手机并允许 USB 调试。

### 设备显示 `offline`

先在 Device Manager 中 Cold Boot。仍无法恢复时关闭模拟器，再重新启动：

```sh
emulator -avd RSS_Android_16
```

只有在快照持续损坏时才使用 Wipe Data；它会删除该虚拟设备中的全部应用数据。

### 模拟器启动很慢或无法启动

- Apple Silicon 使用 `arm64-v8a` 系统镜像。
- Intel Mac 使用 `x86_64` 系统镜像。
- 确认磁盘有足够空间，并且没有同时启动同名 AVD。
- 最简验证设备使用 API 36 的 Default Android System Image，不需要 Google APIs 或 Play Store。

### 同时连接多台设备

先通过 `adb devices` 找到目标序列号，再给命令加 `-s`：

```sh
adb -s 设备序列号 install -r app/build/outputs/apk/debug/app-debug.apk
```

## 6. APK 安装失败

### `INSTALL_FAILED_UPDATE_INCOMPATIBLE`

已安装包与新 APK 的签名不同。最常见情况是用 debug APK 覆盖正式包，或正式构建使用了另一把密钥。

如果设备数据需要保留，不要卸载；改用与已安装包相同的正式密钥重新构建。可以先按[发布与签名](发布与签名.md)比较证书 SHA-256。

确认数据可以丢弃时，才执行：

```sh
adb uninstall com.codex.rssreader
adb install app/build/outputs/apk/debug/app-debug.apk
```

第一条命令会永久删除该安装的本地数据。

### `INSTALL_FAILED_VERSION_DOWNGRADE`

设备上的 `versionCode` 高于待安装 APK。正式版本应提高 `VERSION_CODE` 后重新构建。不要通过卸载规避，除非确认本地数据可以删除。

### 安装空间不足

```sh
adb shell df -h /data
```

删除模拟器中不需要的应用或数据后重试。不要把 Wipe Data 当作第一步。

## 7. 无法添加订阅

应用只接受直接返回 RSS 2.0 或 Atom XML 的 `http`/`https` 地址，不会从普通网页自动发现订阅源，也不会抓取网页全文。

| 界面错误 | 含义与处理 |
|---|---|
| `请输入 http 或 https 订阅地址` | 地址缺少协议，或使用了不支持的协议 |
| `订阅地址无效` | 地址无法解析，或缺少有效主机名 |
| `该订阅源已添加` | 规范化后的同一地址已经存在，不会重复创建 |
| `订阅源请求失败（HTTP 代码）` | 服务端返回非 2xx；检查地址、服务状态、权限或限流 |
| `内容不是 RSS 或 Atom 订阅源` | 地址返回了网页、登录页或其他非支持格式 |
| `订阅内容超过 8 MB` | 单次订阅 XML 超过应用限制 |
| 超时或证书错误 | 网络不可达、来源响应过慢，或 TLS 证书不受设备信任 |

可以在电脑上初步检查响应：

```sh
curl -L -I "订阅地址"
curl -L --max-time 20 "订阅地址" | head
```

响应正文应以 RSS 或 Atom XML 开始。返回 HTTP 200 并不代表内容一定是订阅源；有些站点会对浏览器、地区、登录状态或访问频率返回不同内容。

已验证样例：

```text
https://www.ithome.com/rss/
```

## 8. 刷新失败或没有新文章

- 在订阅页点击刷新，或进入来源后下拉刷新。
- 单个来源失败不会删除缓存文章，也不会阻止其他来源刷新。
- 应用启动时会刷新；从后台返回距上次刷新超过 15 分钟才自动刷新，不运行后台定时任务。
- 连续点击刷新不会创建并行刷新任务，当前刷新结束后再重试。
- 来源 XML 没有新增稳定 ID、链接或内容时，不会创建重复文章。
- 服务器仍在 RSS 中返回已清理文章时，应用会利用去重记录避免把它重新作为未读导入。

如果来源在浏览器中正常而应用持续失败，记录界面错误和发生时间，再抓取 logcat。来源可能针对不同 User-Agent 返回了不同内容。

## 9. 文章数量、顺序或已读状态

以下是当前产品规则，不属于故障：

- 第一次添加来源时，只把时间最新的 20 篇设为未读；更早的文章保留在“全部”中并视为已读。
- 文章列表按最旧优先显示。没有有效发布时间的文章使用首次获取时间排序。
- 打开文章会立即标记已读。
- 向下滚动时，完整划出屏幕顶部的文章也会标记已读；快速划过的中间文章同样处理。
- 当前页面中的文章会保留在原位置并灰显。重新进入默认“未读”列表后，已读文章不再出现；可切换“全部”查看。
- 已读文章从首次标记已读起保留 30 天，在应用启动清理时删除。未读文章一直保留。

如果实际行为与上述规则不同，记录来源、文章标题、操作前后的未读数和完整滚动步骤。

## 10. 正文、图片和原文

- 正文文字来自订阅源本身。来源只提供摘要时，阅读页也只能显示摘要。
- 文字会存入本地数据库；正文图片按需联网加载，离线时可能不显示。
- 图片服务器拒绝外链、防盗链、证书异常或原图已删除时，文字阅读仍应正常。
- “原文”交给系统浏览器；没有可处理网页链接的应用时可能无法打开。
- 字号和阅读位置保存在本机。清除应用数据或卸载后无法恢复。

## 11. GitHub Actions 和 Release

### 构建失败

打开失败的 workflow run，找到第一个红色步骤。使用 GitHub CLI 可查看失败日志：

```sh
gh run list --limit 10
gh run view 运行编号 --log-failed
```

debug workflow 不需要签名 Secrets。release workflow 需要以下四项，名称必须完全一致：

- `ANDROID_KEYSTORE_BASE64`
- `ANDROID_KEYSTORE_PASSWORD`
- `ANDROID_KEY_ALIAS`
- `ANDROID_KEY_PASSWORD`

常见 release 失败原因：

- `ANDROID_KEYSTORE_BASE64 is missing`：Secret 未创建或当前仓库不可用。
- Base64 decode 失败：Secret 内容不完整，或复制时混入空格和其他文字。
- `Keystore was tampered with, or password was incorrect`：keystore 密码错误，或文件内容不是原 keystore。
- `No key found`、alias 相关错误：`ANDROID_KEY_ALIAS` 与 keystore 中的 alias 不一致。
- key password 错误：`ANDROID_KEY_PASSWORD` 不匹配对应私钥。

不要把 Secret 值输出到日志来排查。应在本地用原 keystore 验证 alias 和密码，再重新设置 Secrets。

### Actions 成功但没有 GitHub Release

从 Actions 页面手动运行 `Build Signed Release APK` 只上传保留 30 天的 Artifact。创建长期 Release 必须推送 `v*` 标签：

```sh
git tag -a v0.1.2 -m "Release v0.1.2"
git push origin v0.1.2
```

确认标签已到远端：

```sh
git ls-remote --tags origin v0.1.2
```

如果标签 workflow 成功但 Release 仍缺失，检查 `Publish GitHub Release` 步骤以及 workflow 的 `contents: write` 权限。

## 12. 数据恢复边界

普通刷新失败、来源返回错误、应用强制停止或手机重启，都不应删除已有文章和阅读状态。以下操作会导致数据丢失：

- 在系统设置中选择“清除存储空间”或“清除数据”。
- 执行 `adb shell pm clear com.codex.rssreader`。
- 执行 `adb uninstall com.codex.rssreader`。
- 对模拟器执行 Wipe Data。
- 删除订阅源；该来源的文章和去重记录会同时删除。

正式包的数据目前没有受支持的导出/恢复流程。遇到签名冲突、数据库问题或启动崩溃时，先保留安装和现场，再决定是否清除数据。

```text
版本/提交：
APK 来源：debug / GitHub Release / 本地 release
设备与 Android 版本：
问题发生时间：
订阅源类型：RSS 2.0 / Atom / 不确定
复现步骤：
预期结果：
实际结果与错误原文：
是否稳定复现：
已尝试的操作：
相关 logcat 或 Actions run 链接：
```

提交日志前删除密码、keystore Base64、私有订阅令牌和不希望公开的文章内容。
